接手代码分析：petstore 服务

Claude 生成 · 2026-11-10 · 接手价格服务时复用，勿重复分析

1 · 服务定位

Petstore 是店铺侧的宠物档案与订单核心服务，承接 web、app 与对账系统。契约真源在 specs/petstore/openapi.yaml。

2 · 模块划分

  • pet-core —— 领域模型与校验（Pet / Category / Order）
  • pet-web —— REST 控制器，对应 /api/v1/pets**
  • pet-store-adapter —— 数据访问 + 缓存（Redis）
  • payment-adapter —— 调下游收款服务（dubbo）

3 · 依赖与风险

外部依赖

用户服务（owner 元数据，不可靠，需熔断）、收款服务（dubbo，契约在 order-service 仓）。

已知风险点

# 2026-11 排查记录
1. GET /{petId} 无缓存——高流量路径建议加 CacheAside
2. status 字段 pending→sold 无状态机，对账脚本容错靠重试
3. legacy-inventory 仓 token 已过期，摄取持续 error（见树中 error）

4 · 上手路径

  • 改接口：进 specs/petstore/openapi.yaml，编辑即 commit + push，随后 webhook 自动摄取
  • 联调：前端按契约看 PATH 与 Schema，mock 数据由 spec + 规则生成（P2 I2）
  • 加文档：AI 分析结果以 Markdown 落 docs/ 独立域，链回关联接口
